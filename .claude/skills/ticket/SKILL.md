# 티켓 진행: $ARGUMENTS

1. **읽기**: `docs/80-tasks.md`의 `### $ARGUMENTS` 섹션 전체 → 그 티켓의 "참고" 문서 해당 절 → `docs/90-glossary.md`
2. **선행 확인**: `docs/70-roadmap.md` §1.1에서 이 티켓의 단계와 순서를 찾고, 앞선 티켓의 산출물(파일·테스트)과 §1.2의 사용자 산출물이 실제로 있는지 확인한다. 없으면 멈추고 무엇이 빠졌는지 보고한다
3. **충돌 확인**: 문서끼리 또는 문서와 티켓이 맞지 않으면 구현 전에 사용자에게 묻는다. 답을 받으면 문서를 먼저 고친다 (AGENTS.md §1)
4. **사람 작업 분리**: 🧑 항목은 사용자에게 필요한 것을 구체적으로 요청하고, 나머지만 진행한다
5. **계획 공유**: 만들거나 고칠 파일, 작성할 테스트를 5줄 이내로 보여준다
6. **브랜치**: git 저장소면 `git switch -c t-<번호>-<짧은-이름>`
7. **테스트 먼저**: 수용 기준 중 테스트로 옮길 수 있는 것은 테스트부터 쓴다. 외부 API는 녹화 픽스처
8. **구현**: 티켓 범위만. 범위 밖 필요한 일은 `docs/80-tasks.md` 하단 "제안 티켓" 표에 추가한다
9. **검증**: `make check` (T-001 전에는 해당 도구를 직접 실행). 실패하는 테스트를 지우거나 skip하지 않는다
10. **보고**: 수용 기준 체크리스트를 항목별 근거(테스트 이름, 명령 출력 요약)와 함께 출력. 못 한 항목은 미체크 + 이유
11. **커밋**: `$ARGUMENTS: <요약>` 메시지로 커밋 → 브랜치 push → PR 생성(설명에 수용 기준 체크리스트) → CI 결과 보고. 머지는 사용자 확인 후 rebase 방식
