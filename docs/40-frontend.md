# 40. 프론트엔드 (`apps/web`)

## 1. 디자인 원칙

1. **모바일 우선**: 기준 폭 360px에서 먼저 완성하고 넓힌다. 데스크톱은 최대 폭 720px 단일 열(관리자 화면만 넓게)
2. **큰 글씨·한 화면 한 질문**: 본문 17px, 줄 간격 1.6. 마법사는 화면당 질문 1~3개
3. **숫자가 주인공**: 핵심 숫자(폐업률, 금액, 기한)는 크게, 설명은 그 아래 한 줄
4. **근거는 한 번 탭 거리**: 모든 판단 옆 "근거" 버튼 → 하단 시트
5. **색만으로 의미를 전달하지 않는다**: 배지에는 항상 글자(충족/불충족/확인 필요)
6. **단정하지 않는다**: 통계는 "참고", 판정은 "공고 기준"이라고 항상 표기
7. WCAG 2.1 AA (대비 4.5:1, 터치 영역 44px, 포커스 표시, 폼 라벨)

- 헤더: 서비스명, 메뉴(자리 이력 · 정책자금 · 폐업 지원 · 내 사업장)

## 4. 화면 명세

### 4.1 홈 `/`
- 제목: "어떤 결정을 앞두고 있나요?"
- 카드 3개: **계약할 자리 확인하기**(→ 주소 검색 포커스) · **필요한 자금 마련하기**(→ `/funding`) · **폐업 준비하기**(→ `/closure`)
- 저장된 프로필이 있으면: "○○구 · 분식 · 개업 3년차 사장님" 요약 칩 + 수정 링크

### 4.2 주소 검색 (컴포넌트 `AddressSearch`)
- 입력 300ms 디바운스, 2자 이상에서 호출, 결과 최대 10개
- "현재 위치로 찾기" 버튼(Geolocation 권한 요청 → `/address/reverse`), 권한 거부 시 버튼 숨김. 이미 거부된 상태(Permissions API `denied`)면 처음부터 숨긴다. 버튼을 누른 뒤 거부하면 버튼을 숨기고 화면 안에 "위치 권한이 꺼져 있어요. 주소를 입력하거나 지도에서 골라 주세요."를 보여준다(브라우저 `alert` 금지). 좌표는 서버 로그에 남지 않는다(docs/30 §2, ADR-014)
- "지도에서 고르기" 버튼: 지도(카카오, 지연 로딩)에서 한 점을 찍으면 그 좌표로 `/address/reverse`를 호출해 "현재 위치로 찾기"와 같은 결과를 보여준다. 위치 권한이 필요 없고, 권한을 거부해도 이 버튼은 남는다. **지도에서 고르기를 위한 API를 따로 만들지 않는다.** 결과는 그 지점의 필지 1곳이고, 한 필지에 건물이 여러 개면 여러 항목을 보여줘 사용자가 고른다(docs/30 §2). 원하는 건물이 아니면 다시 찍는다. 주소 검색 결과가 없거나 오류일 때도 이 버튼을 안내한다
- 결과 항목: 도로명 + 지번 + 건물명(도로명이 `null`이면 지번만), `has_history=false`면 회색 + "식품 업소 기록 없음". `pnu`가 `null`인 항목은 고를 수 없게 회색으로 두고 "이 주소는 필지를 확인하지 못했어요"
- `related_pnus`: `[]`이면 따로 안내하지 않는다(확인했고 없음). **`null`이면** 항목 아래에 "같은 건물의 다른 필지 기록은 확인하지 못했어요."(확인 못 함). 빈 목록처럼 다루지 않는다
- 좌표 결과의 `pnu`가 `null`이면(도로·하천 등): "이 지점에서는 필지를 찾지 못했어요. 건물 위를 다시 찍어 주세요."
- 상태: 로딩(스켈레톤 3줄), 결과 없음("주소를 조금 더 자세히 입력해 주세요" — 검색어를 API가 받지 않은 422도 같다), 오류(재시도 버튼)

### 4.3 필지 `/place/[pnu]`
- 주소, 작은 지도(카카오, 지연 로딩), 층 목록(층 · 기록 수 · 영업 중 수)
- 층이 1개이고 층을 알 수 없는 기록이 없으면 바로 층 페이지로 이동
- `records_without_floor > 0`: 층 목록 아래에 **"층을 알 수 없는 기록 {n}건"** 타임라인을 보여준다(T-018에서 결정, 2026-10-13). 층 정보가 하나도 없는 필지가 157,898곳 중 50,066곳(32%)이라, 이 목록이 없으면 그 필지에서는 가게 이력이 하나도 보이지 않는다
  - 항목은 층 이력 타임라인(§4.4-5)과 같다: 상호 · 업태 · 기간 · 기간 길이 · 배지(영업 중/폐업 처리 몰린 날). 세로, 오래된 순
  - 안내 문구: "신고 주소에 층이 적혀 있지 않아 어느 층의 가게인지 알 수 없는 기록이에요. 층별 이력과 통계에는 포함되지 않았어요."
  - **기준율 카드는 보여주지 않는다**(층키가 없어 과거 폐업 횟수를 셀 수 없다). "같은 호수에 새 신고" 배지와 같은 호수 묶음도 없다(층키가 있어야 판정한다)
- **같은 건물의 다른 필지 기록** (T-033, 2026-10-19 결정): 같은 건물인데 다른 지번(관련지번)으로 신고된 기록이 있어(주소 검색 일치율 측정에서 관련지번으로만 일치 32건, 1.60%, `reports/search_match.md`) 그 필지로 가는 링크를 둔다
  - 얻는 방법: 필지 페이지가 **브라우저에서** 기존 `GET /address/search`를 이 필지의 `jibun_label`로 한 번(첫 페이지) 부르고, 결과 중 `pnu`가 이 필지와 같은 항목의 `related_with_history`(docs/30 §2)를 쓴다. 검색으로 들어오든 링크로 바로 들어오든 같은 경로다. 새 API는 없다. 서버 렌더링(ISR)에는 넣지 않는다(외부 API 결과가 하루 캐시에 섞이지 않게)
  - 같은 `pnu` 항목이 여럿이면(한 필지에 건물 여러 개) 목록을 합친다(나온 순서, 중복과 이 필지 자신은 뺀다)
  - 항목마다 `/place/{pnu}` 링크, 링크 글자는 `jibun_label`
  - 합친 목록이 비었으면 따로 안내하지 않는다(확인했고 없음). **같은 `pnu` 항목이 없거나, 호출이 실패했거나, 값이 `null`이면** "같은 건물의 다른 필지 기록은 확인하지 못했어요."(확인 못 함 — 빈 목록처럼 다루지 않는다, ADR-003)
- 이력 없음: "이 필지에는 2026년 {월} 기준 식품 업소 인허가 기록이 없어요"

### 4.4 층 이력 `/place/[pnu]/[floor]` (핵심)

순서:
1. **헤더**: 지번 주소 + 층, 도로명 보조
2. **요약 칩**: 거쳐간 업소 {n}곳(2005년 이후) · 폐업 업소 영업기간 중앙값 {x}년 {y}개월 · 지금 영업 중 {k}곳
3. **기준율 카드** (`BaseRateCard`)
   - 표시: "이 층처럼 과거 폐업이 **{bucket_label}**인 자리에 새로 연 가게는 3년 안에 **{rate}%**가 문을 닫았어요."
   - 비교: "과거 폐업이 없던 자리는 {baseline}%였어요."
   - `{bucket_label}`(T-033, 2026-10-19): 버킷 `0`~`3` → "0회"~"3회", `4+` → "4회 이상". `{snapshot}`은 `snapshot_label`(`2026-11`) → "2026년 11월". `{scope_label}`은 API 값 그대로
   - 보조: "{scope_label} {scale_label} {n}곳 기준 · 95% 신뢰구간 {lo}~{hi}% · {snapshot} 데이터" + 신뢰구간 막대(가로, 두 값 비교)
   - 층 규모(T-019b, docs/10 §7.2): 카드의 값은 이 층과 같은 규모의 자리만으로 낸 값이다. `{scale_label}` = `single` "한 점포가 쓰던 층" / `small` "여러 점포가 함께 있던 층(2~9곳)" / `large` "점포가 많은 층(10곳 이상)". 비교 문구의 기준선도 같은 규모다
   - 고정 문구: "참고 통계예요. 이 자리에 열 가게의 성패를 예측하지 않아요." + "어떻게 계산했나요?" → `/methodology`
   - 숨김: "비슷한 이력의 자리가 충분하지 않아(200곳 미만) 통계를 보여드리지 않아요."
   - 숨김(`hidden_reason = "insufficient_sample"`)은 위 "숨김" 문구다. `base_rate`가 `null`(아직 계산 전)이면 카드 자리에 "이 자리의 통계는 아직 준비 중이에요."만 둔다
   - 숨김(`hidden_reason = "not_confirmed_for_floor_scale"`): 그 규모에서 판정이 깨졌으면(docs/10 §7.3) 카드 대신 **"이 정도 규모의 층에서는 과거 폐업 횟수와 폐업률의 관계가 검증 기준을 통과하지 못했어요"**를 표시한다. 비율·신뢰구간은 보여주지 않고 "어떻게 계산했나요?" → `/methodology` 링크만 둔다
4. **알림** (`notices`): 여러 점포 가능 / 폐업 처리 몰린 날 포함 / 같은 호수에 나중 신고 있음 / 2005년 이전 층 정보 누락
   - 문구(T-033, 2026-10-19). 알 수 없는 값은 보여주지 않는다
     - `multiple_units_possible`: "이 층에는 영업 기간이 한 달 넘게 겹치는 기록이 있어요. 점포가 여러 개였거나 앞 가게의 폐업 신고가 늦어졌을 수 있어요." (겹침은 여러 점포일 수도 신고 지연일 수도 있다 — analysis/README §4.1. 함께 영업했다고 단정하지 않는다, §6)
     - `bulk_closure_present`: "폐업 처리 몰린 날에 폐업된 기록이 있어요. 그 가게들이 실제로 문을 닫은 날은 더 이를 수 있어요."
     - `stale_suspect_present`: "같은 호수로 나중에 다른 가게가 영업 신고를 한 기록이 있어요. 앞 가게의 폐업 신고가 늦어졌을 수 있어요."
     - `pre_2005_floor_missing`: "2005년 이전 기록은 신고 주소에 층이 적혀 있지 않은 경우가 많아요. 층을 알 수 없는 기록은 필지 페이지에서 볼 수 있어요." + 필지 페이지 링크
5. **타임라인** (`FloorTimeline`): 세로, 오래된 순. 항목 = 상호 · 업태 · `2011.03 – 2013.08` · `2년 5개월` · 배지(영업 중/폐업 처리 몰린 날/같은 호수에 새 신고) · 같은 호수 그룹은 같은 색 점 + "같은 호수({ho}호)로 신고된 기록"
   - 기간(T-033, 2026-10-19): 끝은 `closed_on`, 없으면 영업 중·휴업은 "지금"(기간 길이는 `data_as_of`까지), 그 밖은 "날짜 미상"(기간 길이 없음). `opened_on`이 없으면 "개업일 미상"이고 기간 길이 없음. 기간 길이는 두 날짜의 달력 개월 수(끝 날짜의 일이 시작 일보다 작으면 1개월 덜)
   - 배지: `status` `open` "영업 중", `suspended` "휴업"(T-033 추가), 그 밖의 상태는 배지 없음. 요약 칩의 영업기간 중앙값(일)은 1461일 = 48개월로 개월 수(내림)로 바꿔 "{x}년 {y}개월", 값이 없으면 칩을 빼지 않고 "폐업 업소 영업기간 중앙값 알 수 없음"
   - 긴 목록(2026-10-14 결정): API는 이력을 자르지 않고 전부 준다(docs/30 §2). 화면은 처음 일부만 그리고 나머지는 "전체 보기"를 누르면 그린다. 필지 페이지의 층 미상 기록 타임라인(§4.3)도 같다. **처음 그릴 건수는 20건**(T-033, 2026-10-19 — 층 미상 기록의 필지당 99번째 백분위 16건, docs/30 §2. 대부분의 필지·층은 한 번에 다 보인다). 버튼 글자 "전체 보기({n}건)". 같은 호수 그룹 색은 전체 목록 기준으로 정하므로 펼쳐도 바뀌지 않는다
   - "같은 호수에 새 신고" 배지(`stale_suspect`) 설명: "같은 호수로 나중에 다른 가게가 영업 신고를 했어요. 이 가게의 폐업 신고가 늦어졌을 수 있어요." 같은 호 근거일 때만 보여준다. 면적만 같은 경우(`stale_area_match`)는 화면에 내지 않는다(docs/10 §6, ADR-023)
   - "폐업 처리 몰린 날" 배지(`bulk_closure`) 설명: "이날 {관할 이름}에서 평소보다 훨씬 많은 폐업이 한꺼번에 처리됐어요({n}건). 실제로 문을 닫은 날은 더 이를 수 있어요." 해석("행정 일괄 정리")이 아니라 사실만 쓴다(ADR-020). 관할 이름과 건수는 API가 주는 값만 쓴다 — 응답에 포함하기로 결정했고(2026-10-13), 저장은 T-016, 응답 필드는 T-022에서 docs/30을 고쳐 추가한다
6. **행동**: "정보가 잘못됐나요?"(정정 요청 시트)
   - "이 자리로 정책자금 알아보기"(프로필에 `region.sido_code='11'`, `region.sigungu_code` = PNU 앞 5자리를 저장하고 `/funding`): **보류(ADR-030) — 모듈을 다시 시작할 때 넣는다**(2026-10-19, T-033 검토). `/funding` 화면이 없어 지금 넣으면 없는 페이지로 간다
7. 메타데이터: `<title>{지번} {층} 가게 이력 | 가게내비</title>`, 설명에는 평가적 표현 금지
8. 면적(`소재지면적`)은 단위가 확인될 때까지 화면에 내지 않는다(🔎 docs/03 D1, T-033). 지금 API 응답에도 면적이 없다

### 4.5 정책자금 마법사 `/funding`

- 단계 정의는 docs/21 §3. 단계마다 `localStorage` 즉시 저장(`gn.profile.v1`)

- 신용점수 단계: `/funding/credit-bands`로 구간 버튼 생성, 도움말 시트 "신용점수 조회는 점수에 영향을 주지 않아요"

### 4.6 정책자금 결과 `/funding/result`

### 4.9 방법론 `/methodology`
섹션: 데이터 출처와 기준일 · 주소 검색으로 필지를 찾는 정확도(검색 일치율 — 판정용·참고용 값과 Wilson 95% 신뢰구간, 개업연도별로 오래된 기록일수록 낮다는 점, "지번 변경(추정)"을 가를 수 없다는 한계. 판정과 무관하게 싣는다 — docs/50 §7, T-034) · 자리(층키) 정의 · 과거 폐업 횟수·3년 내 폐업 정의 · 폐업 처리 몰린 날의 처리(제외 없음·탐지 규칙·서울 전체 100건 기준 세 가지 비교, ADR-020) · 설정을 하나씩 바꿔 본 결과(편의점 포함, 신고 지연 의심 제외, 층 미상 폐업이 있는 필지 제외 — docs/10 §7.3) · 결과(기준율 표, 로지스틱 결과, 시군구별 결과 점그래프, **시간 외 검증 AUC: 개별 예측력은 매우 작다는 사실**) · 한계 · 갱신 주기. 데이터는 `/stats/model-card`(모형 카드 + 검색 일치율, docs/30).
- **화면의 숫자는 전부 응답에서 만든다**(T-034). 정의에 들어가는 고정값(1,095일, 2005-01-01, 버킷 경계, 층 규모 경계, 30일 겹침 기준, 급증일 규칙의 30건·10배, W0 정의의 100건, 표시 조건 200곳)만 정의 문장으로 쓴다. 비율 표기는 §6(소수 첫째 자리)
- 층 규모별 결과는 판정이 깨진 규모(`holds = false`)도 싣고 "검증 기준 통과 못 함"으로 표시한다(docs/10 §7.3)
- 시군구별 결과 점그래프: 시군구마다 1회당 OR 점과 95% 구간 선, 1의 기준선. OR이 없는 시군구는 "계산하지 못했어요"로 목록에 남긴다. 색만으로 구분하지 않는다
- AUC 문장: "과거 폐업 횟수를 넣어도 시간 외 검증 AUC가 {auc_base} → {auc_with_prior}예요. 한 가게가 3년 안에 폐업할지를 가려내는 힘은 매우 작아요. 이 숫자로 개별 가게의 앞날을 예측하지 않아요." (ADR-005)
- 모형 카드나 검색 일치율이 아직 없으면(`null`) 그 숫자 자리에 "아직 계산하지 않았어요"를 쓰고 정의·한계 문장은 그대로 보여준다

### 4.10 관리자 `/admin`
- 검수 화면: 좌측 원문(근거 문장 하이라이트, 줄 번호) / 우측 규칙 폼(필드별 승인·수정, `needs_review` 빨간 표시, 자동 검증 결과 배지) / 상단 타이머(필드 편집 시간 자동 측정 → `seconds_spent`)
- 대기열 표, 변경 감지 목록(diff), 평가 실행 이력(지표 + 신뢰구간 표), 정정 요청 처리

## 6. 문구 규칙 (`lib/format.ts`와 일치)

- 해요체. 명령형보다 안내형("신청하세요" → "신청할 수 있어요", 단 기한·금지 안내는 "~해야 해요")
- 금액: `30000000` → `3,000만 원`, `450000` → `45만 원`, `120000000` → `1억 2,000만 원`. 만 원 미만이 남으면 `1,234만 5,678원`, 만 원 미만뿐이면 `5,000원`
- 비율: 소수 첫째 자리 `43.4%`. 신뢰구간 `(95% 신뢰구간 39.2~47.1%)`. API의 소수 문자열(`"0.4340"`)을 부동소수 없이 바꾸고, 둘째 자리에서 반올림(0.5는 올림)
- 날짜: `2026년 11월 20일`, 타임라인 기간 `2011.03 – 2013.08`, 기간 길이 `2년 5개월`
- **금지 표현**: 망한 자리, 위험한 자리, 저주, 흉지, 대박, 승인 보장, 대출 확정, 100%, 무조건, 누구나
- 검증하지 못한 해석을 사실처럼 쓰지 않는다: "행정 일괄 정리" 대신 "폐업 처리 몰린 날"(ADR-020), "폐업 신고가 늦어진 것으로 보여요" 대신 "같은 호수로 나중에 다른 가게가 영업 신고를 했어요. … 늦어졌을 수 있어요"(ADR-023)
- 상호는 데이터 그대로 표시하되 평가 문장 안에 상호를 넣지 않는다

## 7. 상태·오류·오프라인

- 로딩: 스켈레톤(레이아웃 이동 없음). 평가 요청 3초 넘으면 "계산 중이에요" 문구
- 오류: 사람이 읽는 문장 + 재시도. `request_id`는 접힌 "문제 신고용 정보"에만
- 오프라인(PWA): 앱 셸과 마지막으로 본 자리 페이지만 표시, 평가는 "인터넷 연결이 필요해요"

## 8. PWA

- `app/manifest.ts`: name "가게내비", short_name "가게내비", display `standalone`, 시작 URL `/`, 아이콘 192/512(maskable 포함)
- Serwist 서비스 워커: 정적 자산 캐시 우선, `/place/*` 네트워크 우선(실패 시 캐시), `/api/v1/*/evaluate`는 캐시 금지

- 서비스 워커는 프로덕션 빌드에서만 만든다(개발 서버에서는 꺼짐). 설치 가능 여부는 e2e `tests/e2e/pwa.spec.ts`가 Chrome 판정(`Page.getInstallabilityErrors`)으로 확인한다 — Lighthouse 12부터 PWA 항목이 없어졌다(T-030)

## 9. 검색 노출 (SEO)

- **Gate 1 전에는 전체 `noindex`.** Gate 1(정정 요청 처리 체계 포함) 통과 후 기록 2건 이상인 층 페이지만 색인 허용

- 구조화 데이터는 사용하지 않음(평가 정보로 오해될 소지)

## 10. 분석 이벤트 (개인정보 없음, 자체 호스팅 도구)

`address_search`, `place_view{floor_count}`, `floor_view{has_base_rate}`, `evidence_open{module}`, `methodology_open`, `wizard_step{module, step, unknown}`, `evaluate_submit{module}`, `evaluate_result{module, plan_count, unknown_count}`, `correction_submit`. 프로필 값·주소·금액은 이벤트에 넣지 않는다.

방문 측정(docs/70 §5, ADR-027): 서버에 방문자 식별자를 보내지 않는다. 브라우저에는 첫 방문 날짜와 "이미 보냈음" 표시만 저장하고, 익명 이벤트 두 가지 — "첫 방문(날짜)", "7일 안 재방문(첫 방문 날짜)" — 를 각각 브라우저당 한 번만 보낸다. 서버는 식별자·IP·User-Agent를 저장하지 않는다(봇 거르기는 받을 때만 판단). `/privacy`의 스위치를 켠 브라우저(내 기기 제외도 같은 플래그)는 이 절의 **어떤 이벤트도 보내지 않는다**. "도움이 됐나요" 클릭 이벤트와 구현은 T-104.
