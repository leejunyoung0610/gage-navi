# 00. 제품 정의

> 버전 1.0 · 2026-10-12 · 상태: 확정 (변경 시 하단 변경 이력에 기록)

## 1. 한 줄 정의

소상공인이 **자리 계약 · 자금 조달 · 폐업**이라는 세 번의 결정에서, "찾기"가 아니라 **"내 상황에서 무엇을, 어떤 순서로"**를 판단하도록 돕는 웹 서비스. 모든 판단에는 공공데이터 또는 공고 원문 근거가 붙는다.

## 2. 왜 이 서비스인가 (시장 공백)

조사 결과(2026-10), 두 시장 모두 **찾기·신청하기는 디지털화가 끝났고 판단 단계가 비어 있다.**

| 단계 | 이미 있는 것 | 비어 있는 것 |
|---|---|---|
| 창업 | 상권분석(소상공인365, 서울시 상권분석서비스, 통신사 사장님 앱), 지원사업 검색(K-Startup, 기업마당), AI 사업계획서 | **계약하려는 특정 점포 단위의 이력** |
| 운영 | 정책자금 비대면 신청(보증드림, 신보 앱, 대리대출 비대면 원스톱), 정책지원금 조회(토스·네이버), 정부 통합 플랫폼 AI 추천(2026 시범) | **여러 기관 자금의 조합·순서 판단** — 현재 브로커가 승인액의 5~6.6% 수수료를 받고 판매(언론 보도, 2026-04) |
| 폐업 | 희망리턴패키지 누리집, 지자체 공고 | **중복·순서 제약 아래 지원 조합과 행정 타임라인** |

## 3. 사용자

| 페르소나 | 상황 | 핵심 질문 | 사용 기기 |
|---|---|---|---|
| P1 예비 창업자 | 상가 2~3곳을 보러 다니며 계약 직전 | "이 자리 전에 뭐였고, 오래 버텼나?" | 휴대폰 (현장) |
| P2 운영 중 사장님 | 운전자금이 필요, 은행 대출이 어렵다고 들음 | "브로커 없이 내가 받을 수 있는 정책자금과 신청 순서는?" | 휴대폰·PC |
| P3 폐업 예정 사장님 | 1~3개월 안에 폐업 예정 | "철거비·컨설팅 지원을 놓치지 않으려면 무엇을 먼저?" | 휴대폰 |

공통: 디지털 숙련도가 높지 않다고 가정한다. 큰 글씨, 단계형 입력, 용어 도움말이 기본이다.

## 4. 핵심 원칙 (모든 모듈 공통, 위반 시 머지 금지)

1. **판단은 결정론적 코드가 한다.** LLM은 공고 원문에서 조건을 *추출*할 때만 쓰고, 자격·금액·순서 판단에는 절대 쓰지 않는다. (ADR-001)
2. **사람이 검수하지 않은 규칙은 배포되지 않는다.** (ADR-002)
3. **모르면 모른다고 한다.** 정보가 없거나 원문이 모호하면 "확인 필요"(3치 판정). 억지로 참/거짓을 만들지 않는다. (ADR-003)
4. **모든 판단과 숫자에 근거를 붙인다.** 공고 원문 문장, 데이터 출처와 기준일, 규칙 버전. (ADR-004)
5. **근거 없는 예측 숫자를 만들지 않는다.** 선정 확률, 위험 점수, 성공 확률을 보여주지 않는다. 통계는 "비슷한 경우들이 실제로 어땠는지"만 보여준다. (ADR-005)
6. **돈을 받지 않고, 대신 신청하지 않는다.** 수수료·신청 대행·금융상품 중개·보험 연계 없음. (docs/60)

## 5. 범위

### 5.1 MVP 범위 (Gate 3까지, 순서는 docs/70)

| 항목 | 범위 |
|---|---|
| 지역 | **서울특별시** 전체 (3개 모듈 공통) |
| 자리 이력 업종 | 일반음식점, 휴게음식점, 제과점영업 (인허가 데이터 식품 3종) |
| 자리 이력 단위 | **층 단위 이력** + **호수 일치 기록 표시**. 호실 추정 연결은 품질 게이트 통과 시에만 (§5.3) |
| 정책자금 대상 | 소상공인시장진흥공단 정책자금(2026 공고), 서울신용보증재단 보증·서울시 소상공인 자금(이차보전 포함). 최종 목록은 T-060a에서 확정 |
| 폐업 지원 대상 | 희망리턴패키지(원스톱폐업지원 4종, 전직장려수당, 재기사업화, 경영개선), 서울시 폐업 지원사업, 통합 폐업 신고·부가세 확정신고 안내 |
| 플랫폼 | 웹(Next.js) 모바일 우선 반응형 + PWA. 로그인 없음 |
| 사용자 데이터 | 사업장 프로필은 **브라우저에만 저장**. 서버는 요청을 처리만 하고 저장하지 않음 |

### 5.2 비목표 (MVP에서 하지 않음 — 제안이 와도 백로그로만)

- 정책자금·지원사업 **신청 대행**, 서류 작성 대행, 사업계획서 작성
- 수수료, 유료 기능, 광고, 업체(철거·컨설팅·세무·법률) 연결
- 시중은행 대출상품 비교·추천·연결 (금융상품 중개 해당 소지)
- 선정·승인 확률, 자리 위험 점수, 매출 추정, 상권 분석
- 로그인, 알림(푸시·이메일·알림톡), 네이티브 앱
- 서울 외 지역, 식품 3종 외 업종

### 5.3 단계적으로 켜는 기능 (게이트 조건부)

| 기능 | 켜는 조건 |
|---|---|
| 호실 추정 연결 표시 | 구 단위 hold-out 평가에서 쌍 정밀도 ≥ 0.90 이면서 재현율 ≥ 0.40 (docs/50 §4) |
| 정책자금 모듈 공개 | Gate 2 통과 (docs/50 §7). 미통과 시 "베타 — 결과를 그대로 믿지 마세요" 배너와 함께 비공개 링크로만 |
| 폐업 모듈 공개 | Gate 3 통과 |

## 6. 모듈별 사용자 가치와 출력

### 6.1 자리 이력 (P1)

입력: 주소 검색(또는 지도에서 선택) → 층 선택
출력:
- 그 층을 거쳐간 업소 타임라인 (상호, 업태, 영업 기간, 같은 호수로 신고된 기록 묶음 표시)
- 요약: 2005년 이후 거쳐간 업소 수, 폐업 업소의 영업기간 중앙값
- **참고 통계**: "이 층처럼 과거 폐업이 N회인 자리에 새로 연 가게는 3년 안에 X%(95% 신뢰구간 a~b%)가 문을 닫았어요. 과거 폐업이 없던 자리는 Y%였어요." 표본 200개 미만이면 표시하지 않음
- 데이터 한계 고지 (층 정보 누락, 폐업 처리가 몰린 날, 신고 지연)

### 6.2 정책자금 (P2)

입력: 사업장 프로필(단계형) + 필요 금액·용도
출력:
- 사업별 **자격**(충족/불충족/확인 필요) × **접수 상태**(접수예정/접수중/마감, 조기마감 가능)
- **추천 계획 2안**: ① 필요 금액을 가장 낮은 비용·높은 확실성으로 채우는 안(기본) ② 받을 수 있는 최대 한도 참고안(빚이 늘어난다는 경고와 함께)
- 신청 순서와 선행 조건(교육 이수 등), 순서가 바뀌면 한도가 줄어드는 경우 경고
- 근거: 공고 원문 문장, 확인일, 규칙 버전
- 브로커 주의 안내(공식 신고 경로 링크)

> 차별점: 브로커는 수수료가 금액에 비례하므로 **한도 최대화**를 판다. 이 서비스의 기본 목적함수는 **필요한 만큼을 가장 싸고 확실하게**다.

### 6.3 폐업 지원 (P3)

입력: 프로필 + 폐업 예정일/폐업일, 점포 사용 형태, 면적(단위·기준), 철거 견적, 임대차 만료일, 수혜 이력
출력: 자격 × 접수 상태, 예상 지원액(실비 반영), 추천 조합, 행정 타임라인(부가세 확정신고 기한 포함), 놓치면 손해 보는 함정 체크리스트, 경영개선 지원(폐업하지 않는 선택지) 안내

## 7. 성공 기준

### 7.1 포트폴리오 성공 기준 (1차 목표, Gate 3 시점에 전부 충족)

| # | 기준 | 측정 |
|---|---|---|
| S1 | 배포된 URL에서 3개 모듈이 동작 (정책자금·폐업은 게이트 미통과 시 베타 표시) | 데모 시나리오 3개 수동 확인 + Playwright e2e 통과 |
| S2 | 자리 이력 통계가 W0 분석을 재현 | 재현 테스트 통과 (docs/50 §3) |
| S3 | 규칙 추출 정확도를 **테스트셋**으로 측정하고 부트스트랩 신뢰구간과 함께 보고 | `eval_run` 기록 + 평가 리포트 |
| S4 | 규칙 엔진 속성 기반 테스트 통과, 뮤테이션 점수 ≥ 80% (`rules/engine` 패키지) | CI 리포트 |
| S5 | 방법론 페이지 공개: 데이터, 정의, 한계, 모형 결과(유의성과 낮은 변별력 모두) | 페이지 존재 |
| S6 | 설계 문서·ADR·평가 리포트·2분 데모 영상 | 저장소 |

### 7.2 제품 신호

**사전 등록 기준 — 수요 검증 실험** (Gate 1 공개 후 28일, 알리는 곳 3곳 이상). 측정 정의와 판정표의 정본은 docs/70 §5. 결과를 본 뒤에는 기준을 바꾸지 않는다. 바꿔야 하면 측정 전에 ADR로 남긴다.

| 판정 | 조건 |
|---|---|
| 계속 | 외부 순방문(내 기기 제외) 200 이상, 그리고 ("계약 판단에 도움이 됐나요?" 응답 20건 이상 중 "예" 60% 이상 또는 7일 안 재방문율 15% 이상) |
| 방향 수정 | 외부 순방문 200 이상인데 위 조건 미달 → 대상과 질문을 다시 정의 |
| 연장 | 외부 순방문 100~199 → 알리는 곳을 늘려 28일 한 번만 연장 |
| 중단 | 외부 순방문 100 미만 → 기능 추가를 멈추고 포트폴리오로 마감, 데이터 갱신만 유지 |

**참고 지표** (목표치 없음, 기록만)

- 자리 페이지: 검색 유입 수, 페이지당 체류, 근거·방법론 클릭률, 필지·층 페이지 조회, 정정 요청·피드백
- 정책자금: 입력 완료율, 근거 클릭률, "확인 필요" 비율

## 8. 열린 질문 (결정 시 ADR로 기록)

- 서비스 정식 이름
- 자리 페이지를 검색엔진에 색인시킬 범위 (건물주 정정 요청 대응 체계가 먼저 필요 — docs/60)
- 정책자금 모듈의 신용점수 입력 방식 (구간 선택이 기본안 — docs/21 §3)
