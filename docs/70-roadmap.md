# 70. 로드맵 (두 갈래, 포트폴리오 우선)

- 날짜를 정해 두지 않는다. **순서와 게이트 조건**만 정한다. 구현은 Claude Code가 티켓 단위로 하고, 일정은 사용자 작업(라벨링·검수·확인)이 정한다
- 사용자 작업 시간: **주 10시간** (평일 1시간, 주말 2~3시간)
- 시간이 모자라면 §3 축소 규칙을 적용한다. 일정이 아니라 **범위를 줄인다**
- 티켓 상세·수용 기준은 docs/80. **티켓 순서의 정본은 이 문서 §1**이다
- **정책자금(Gate 2)·폐업 지원(Gate 3)은 보류다(ADR-030, 2026-10-15).** Gate 1 이후 트랙은 자리 이력 확장(§1.1 I단계). 아래 보류 표시가 붙은 단계·작업은 지우지 않고 남겨 둔다
- (보류 전 계획) 2026년 공고로 Gate 2·3까지 간다. 2027년 공고는 기다리지 않고, 게시되면 변경 감지(T-050) 데모에 쓴다

## 2. 라벨링 운영

- 공고 1건 평균 약 45분 가정 → 30건에 약 22시간
- 순서: **dev 18건을 먼저**, 그다음 test 12건. **test 라벨링은 프롬프트 개발(T-052)이 시작되기 전에 끝낸다.** 분할은 T-060a에서 후보 목록을 만들 때 seed로 한 번 고정
- 형식: T-040(DSL 모델) 전에는 `docs/20 §2.3` 예시 구조를 따른 JSON 파일 + 근거 인용(사람이 직접). T-040 완료 후 전부 스키마 검증해 고치고, T-056에서 `eval_case`로 적재
- T-052를 시작한 뒤에는 프롬프트를 고치는 동안 test 공고를 열람·실행하지 않는다(docs/50 §5). 라벨 파일 위치: `eval/labels/{dev,test}/`

## 3. 일정 축소 규칙 (미리 합의)

C·E·F·G·H 보류(ADR-030) 동안 E·H단계·Gate 2에 걸린 줄은 적용하지 않는다.

| 조건 | 줄이는 것 |
|---|---|
| E단계에 들어갈 때 Gate 1 미통과 | Gate 1을 먼저 끝내고, 관리자 검수 화면(T-054)을 JSON 편집기 수준으로 축소(6h → 3h) |
| 구현 갈래가 사용자 산출물을 2주 넘게 기다림 | 폐업 모듈을 희망리턴패키지만으로 축소(서울시 사업 제외), 정답셋 test를 10건으로 |
| H단계에 들어갈 때 Gate 2 미통과 (법률 검토 미완 포함) | 정책자금은 베타 배너 + 비공개 링크로 유지하고 H를 진행한다. Gate 2 보완을 먼저 한다 |
| 사용자 작업이 주 10시간 미만인 주가 2주 연속 | 위 축소를 앞당겨 적용하고 이 표에 기록 |
| 언제든 | **줄이지 않는 것**: 테스트, 게이트 체크리스트, 평가 리포트(신뢰구간 포함), 법적 금지 사항, 코드 이해 노트 |

## 5. 수요 검증 실험 (Gate 1 공개 후 28일, 사전 등록 기준)

아래 기준은 결과를 보기 전에 커밋했다(2026-10-13). **결과를 본 뒤에는 바꾸지 않는다. 바꿔야 하면 측정 전에 ADR로 남긴다** (docs/50 §7 사전 등록 기준).

- **기간**: 공개 후 28일
- **알리는 곳**: 3곳 이상. 광진구 자리 이력 페이지 링크를 자영업자·예비 창업자 커뮤니티 등에 공유한다(커뮤니티 규칙 준수, 광고성 표현 금지). 공유 글·날짜·채널을 기록한다
- **측정**
  - **외부 순방문**: 서버가 받은 **"첫 방문(날짜)" 이벤트 수**. 서버에 방문자 식별자를 보내지 않는다(ADR-027) — 브라우저에는 첫 방문 날짜와 "이미 보냈음" 표시만 저장하고, 서버는 익명 이벤트 두 가지("첫 방문(날짜)", "7일 안 재방문(첫 방문 날짜)")만 받는다. 각각 브라우저당 한 번만 보낸다. 서버는 식별자·IP·User-Agent를 저장하지 않는다(봇 거르기는 받을 때만 판단하고 저장하지 않는다). 한계: 한 사람이 기기(브라우저) 두 대를 쓰면 2명으로 세진다. 브라우저 저장소를 지우거나 시크릿 창을 써도 새 방문자로 세진다. 서버는 중복·조작된 이벤트를 가려낼 수 없다
  - **통계에서 빠지기**: `/privacy`에 "기기에 저장하는 값, 목적, 끄는 방법"을 적고(개인정보 보호법 제30조 제1항 제7호 — docs/60 §5) 끄는 스위치를 둔다. 켜면 그 브라우저는 **아무 이벤트도 보내지 않는다**. 한계: 끈 방문자는 순방문·재방문·"도움이 됐나요" 집계에 들어가지 않아 실제보다 적게 세지고, 끈 수는 알 수 없다
  - **내 기기 제외**: 위와 같은 브라우저 플래그를 내 브라우저에서 켠다(예: 특정 주소로 한 번 들어가면 켜진다)
  - 필지·층 페이지 조회
  - **재방문율**: 분모는 28일 중 1~21일차에 처음 온 순방문자(7일 뒤까지 관찰할 수 있는 사람만) — 첫 방문 날짜가 1~21일차인 "첫 방문" 이벤트 수. 분자는 그중 첫 방문 다음 날부터 7일 안에 **다른 날** 다시 온 사람 — 첫 방문 날짜가 1~21일차인 "7일 안 재방문" 이벤트 수. 날짜는 한국 시간 기준
  - 정정 요청·피드백
  - 층 페이지의 "계약 판단에 도움이 됐나요? 예/아니오" — 개인정보 없이 클릭 수만
- **판정**

  | 판정 | 조건 | 조치 |
  |---|---|---|
  | 계속 | 외부 순방문 200 이상, 그리고 (예/아니오 응답 20건 이상 중 "예" 60% 이상 **또는** 재방문율 15% 이상) | 계속 진행 |
  | 방향 수정 | 외부 순방문 200 이상인데 위 조건 미달 | 대상과 질문을 다시 정의한다 |
  | 연장 | 외부 순방문 100~199 | 알리는 곳을 늘려 28일 **한 번만** 연장한다 |
  | 중단 | 외부 순방문 100 미만 | 기능 추가를 멈추고 포트폴리오로 마감한다. 데이터 갱신만 유지한다 |

- **연장**: 연장하면 **연장한 28일만** 같은 판정표로 본다(56일 합계로 보면 기준이 사실상 절반으로 낮아진다). 연장은 한 번뿐이고, 연장 뒤에도 외부 순방문이 200 미만이면 **중단**이다
- 피드백 내용(어떤 정보를 더 원하는지)은 판정과 별개로 백로그에 기록한다
- 측정값과 판정은 기준을 커밋한 날짜·측정 기간과 함께 `reports/`에 남긴다
