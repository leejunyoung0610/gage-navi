## 3. 자리 통계 재현 테스트

- `tests/integration/test_w0_reproduction.py`: 서울 일반음식점 2026-10-08 스냅샷(UTF-8 변환 파일, 경로는 환경 변수 `W0_SEOUL_CSV` — 없으면 skip하고 사유 출력)으로 `method_version='w0'` 계산
- 기대값은 `analysis/README.md` §4.2~§4.5의 숫자이고, 테스트가 읽는 정본은 `tests/integration/w0_expected.json`이다(docs/10 §7.4). **테스트 코드보다 먼저 커밋했다**(T-020, 2026-10-13)
  - 기대값 v2 (2026-10-13 정정): 첫 기대값(v1)으로는 재현되지 않았고, 원인은 원 스크립트가 쉼표가 든 면적 880건(1,000㎡ 이상 점포)을 빠뜨린 것이었다. 스크립트의 면적 읽기만 고쳐 같은 원본으로 다시 돌린 출력에서 v2를 만들었고(서비스 결과에서 옮기지 않았다), **v2로 테스트를 돌리기 전에 커밋했다**. v1은 `w0_expected_v1.json`에 보관한다. 서비스 `w0` 모드는 특별 처리 없이 `parse_area`를 쓴다
- **허용 오차 = 리포트의 반올림 단위** (2026-10-13 사용자 결정. 이전 기준 "n ±1%, 비율 ±0.3%p, OR ±0.005"를 대체). 같은 파일·같은 정의면 결과가 같아야 하므로 여유를 두지 않는다
  - 건수(코호트 n, 버킷별 n, 시군구별 n, 시군구 요약 개수): **정확히 일치**
  - 비율: `100 × 사건/n`을 소수 첫째 자리로 반올림한 값이 일치 (0.1%p 단위). 모형 카드의 넷째 자리 값을 다시 반올림하지 않는다(이중 반올림)
  - 오즈비와 95% 구간: 소수 셋째 자리로 반올림한 값이 일치. p값: 유효숫자 둘째 자리(`%.1e`). AUC: 소수 넷째 자리
- **다르게 나오면 허용 오차를 늘리거나 기대값을 고치지 않는다.** 어느 값이 얼마나 다른지와 원인(정의 차이·입력 차이·수치 계산 차이)을 먼저 사용자에게 보고하고, 결정을 받은 뒤 문서를 고친다
- 식품 3종 `2026.10.1` 결과는 기대값 고정 없이 `model_card`에 기록하고, 방법론 페이지에 표시. 결론이 유지되는지는 docs/10 §7.3의 판정 기준 (a)(b)로 본다(기본 설정과 민감도 설정 전부). **한 설정에서라도 깨지면**(예: OR의 95% 신뢰구간 하한이 1 이하) `base_rate`·`model_card`를 쓰지 않고 멈추고, 화면 카드와 방법론 문구를 어떻게 할지 사용자가 정한 뒤 ADR을 추가한다
- 층 규모별(단독 / 소형 복수 / 대형)로도 (a)(b)를 다시 적용한다(T-019b, docs/10 §7.3). 규모 하나가 깨지면 멈추지 않고, 그 규모의 기준율을 `base_rate`에 쓰지 않으며 화면은 "이 정도 규모의 층에서는 과거 폐업 횟수와 폐업률의 관계가 검증 기준을 통과하지 못했어요"를 표시한다

## 4. 규칙 엔진

### 4.1 단위 테스트 필수 항목
3치 진리표 전부(all/any/not × 자식 조합), 모든 연산자 × (스칼라·구간·None), 경과 개월 경계(월말, 윤년), 접수 상태 경계일(시작일·마감일 당일), 금액 타입별 계산과 플래그, 평→㎡ 변환과 반올림, cap_group 최솟값 처리, DFS 동률 해소

### 4.2 속성 기반 테스트 (Hypothesis)
| ID | 속성 |
|---|---|
| P1 결정론 | 같은 (사실, 규칙, 기준일, 목적) → 같은 `Evaluation` (직렬화 비교) |
| P2 정보 단조성 | `None`인 사실을 아무 구체값으로 채워도, 원래 MET 또는 NOT_MET이던 사업 판정은 바뀌지 않는다 (구간을 좁히는 경우도 동일) |
| P3 구간 일관성 | 구간 `[x, x]`의 평가 = 스칼라 `x`의 평가 |
| P4 면적 단조 | `per_area` 금액은 면적에 대해 감소하지 않는다 |
| P5 상한 | `cap_krw`가 있는 모든 금액 ≤ `cap_krw` / `per_area` 금액 ≤ 견적 공급가액(있으면) |
| P6 충돌 | 어떤 계획에도 `apply` 충돌 쌍이 함께 없다 |
| P7 배분 | 각 `allocated ≤ 가용 한도(그 순서 기준)`, `need_cover`의 배분 합 ≤ 필요 금액, cap_group 합 ≤ cap − 기존 잔액 |
| P8 최적성 | 후보 ≤ 6개에서 DFS 결과의 목적함수 값 = 전수 열거의 최적값 |
| P9 위상 순서 | 타임라인 순서가 모든 `before/after` 간선을 지킨다 |
| P10 설명 완전성 | 생성된 모든 trace·경고 키에 템플릿이 존재한다 |

### 4.3 시나리오 테스트
docs/21 §8 (F-S1~S10), docs/22 §7 (C-S1~S12). 가상 규칙 픽스처는 `tests/fixtures/rules/`에 두고 파일 첫 줄 `"_comment": "가상 예시 — 실제 사업 아님"`.

### 4.4 골든 테스트 (실제 규칙)
승인된 실제 규칙마다 사람이 공고 원문만 보고 손으로 판정한 프로필 **최소 2개(충족 1, 불충족 1)** 를 `tests/golden/{program_id}.yaml`에 작성. 규칙 새 버전 승인 시 CI에서 전부 통과해야 배포.

### 4.5 호실 연결 연구 (docs/10 §8)
시군구 hold-out 평가 스크립트 `jobs.eval_unit_matching` → 쌍 P/R/F1, B-cubed를 리포트로 저장. 게이트: test 시군구에서 P ≥ 0.90, R ≥ 0.40.

## 7. 공개 게이트

### 사전 등록 기준 (결과를 보기 전에 정한 기준)

아래 기준은 **측정하기 전에** 이 문서에 커밋했다(2026-10-13). 수요 검증 실험의 기준(docs/70 §5)도 같은 규칙을 따른다.

- **결과를 본 뒤에는 기준(정의·분모·구간·조치)을 바꾸지 않는다.** 바꿔야 하면 **측정 전에** ADR로 남기고 이 문서를 고친다. 측정한 뒤에 바꾼 기준은 사전 등록으로 부르지 않는다
- 리포트에는 기준을 커밋한 날짜(커밋 해시)와 측정한 날짜를 함께 적는다

| 지표 | 사전 등록 여부 | 이미 본 값 |
|---|---|---|
| 검색 일치율 | 사전 등록 | 없음. 측정은 T-021b. T-021에서 녹화한 응답 7건은 인허가 기록에서 고른 주소가 아니고(공식 가이드 예시 주소 등 — `jobs/record_juso_fixtures.py`), 인허가 기록의 PNU와 비교하지 않았다 |
| 최근 기록 층 확인율 | **사전 등록 아님 — 관련 값을 본 뒤 정한 기준** | 2016-01-01 이후 값은 재지 않았다. 같은 정의의 2005년 이후 개업분은 82.1%(일반음식점, W0 — analysis/README §4.1, 구별 57.9~96.2%)이고 DV7이 스냅샷마다 계산한다. 2016년 이후는 그 부분집합이다 |
| 수요 검증 (docs/70 §5) | 사전 등록 | 없음 (공개 전) |

#### 검색 일치율

- **측정**: 도로명주소와 지번주소가 **둘 다 있는** 인허가 기록에서, 도로명주소로 검색해 찾은 필지가 지번주소로 만든 PNU(docs/10 §2.1)와 같은 비율
- **표본**: 도로명주소·지번주소가 둘 다 있고 지번 PNU가 있는 기록(측정 시점의 최신 스냅샷)에서 무작위 **2,000건**. seed는 **20261013**으로 고정한다. 뽑는 방법(정렬 키·난수 함수)은 측정 잡 코드와 리포트에 적는다
  - **뽑는 방법** (측정 전에 정함, 2026-10-13 — `app/address/search_match.py`): 모집단은 `license_record`에서 `pnu`가 있고 `road_addr`·`jibun_addr`가 빈 문자열이 아닌 기록. 기록마다 `sha256("{seed}:{license_type}:{mgmt_no}")`의 16진 문자열을 구해 **오름차순으로 앞 2,000건**을 뽑는다. 난수 함수를 쓰지 않아 언어·라이브러리 버전이 달라도 같은 표본이 나온다. 재측정은 seed만 20261014로 바꾼다
- **분모에서 빼는 것**: 지번 PNU를 만들지 못한 기록. PNU 생성 실패율은 따로 잰다(DV6, 0.1062% — reports/pnu_failures.md). 대신 **PNU 성공률 × 검색 일치율**을 종단 값으로 함께 보고한다
- **검색어**: 도로명주소의 기본부(시도~건물번호)만 쓴다. 층·호 같은 상세주소는 뺀다(사용자가 실제로 넣는 형태에 가깝게)
  - **만드는 법** (측정 전에 정함, 2026-10-13): 도로명주소에서 **첫 쉼표 또는 첫 여는 괄호 앞까지**를 잘라 공백을 하나로 줄인다(예: `서울특별시 중구 을지로 지하 88, 374호 (을지로2가)` → `서울특별시 중구 을지로 지하 88`). 그 뒤 주소 검색 프록시와 같은 검색어 정제(`clean_keyword`)를 거쳐 보낸다. 요청도 프록시와 같다(첫 페이지, 10건)
- **일치**: 검색 화면 첫 페이지에 보일 후보(최대 10개 — docs/40 §4.2) 중 하나의 PNU가 지번 PNU와 같으면 일치. 건물 하나가 여러 필지면 그중 하나가 같으면 일치
- **실패로 세는 것**: 검색 결과 없음, 후보 중에 같은 PNU 없음, 검색어 오류(아래), 통신 오류. 통신 오류(시간 초과, 연결 실패, HTTP 200이 아닌 응답, JSON이 아닌 응답)는 **2번까지 재시도**하고(모두 3번 호출), 끝까지 오류면 실패로 센다
- **호출 절차** (측정 전에 정함, 2026-10-13 — ADR-028)
  - **1초에 1건, 순차 호출**(동시에 여러 건을 보내지 않는다. 재시도도 같은 간격을 지킨다). 이유: 공식 문서에서 호출 한도 숫자를 찾지 못했고(`data/README.md` "도로명주소 검색 API 이용 조건"), 과한 호출은 IP 차단으로 이어질 수 있어 보수적으로 잡았다. 표본 2,000건이면 약 34분
  - **도로명주소 API가 돌려주는 오류코드(`errorCode`가 `0`이 아닌 값)는 두 종류로 나눈다** (2026-10-13 고침, 측정 전 — ADR-028 개정). 나눈 기준은 공식 가이드 「검색API 활용 가이드」 2.2 에러코드 표다

    | 종류 | 오류코드 (가이드의 오류메시지) | 처리 |
    |---|---|---|
    | **접근 문제** | `-999`(시스템에러), `E0001`(승인되지 않은 KEY), `E0014`(개발승인키 기간 만료), **그리고 아래 "검색어 문제"에 없는 모든 코드**(가이드 표에 없는 코드 포함 — 호출 과다로 보이는 응답도 여기) | **바로 멈추고 보고한다.** 그 기록을 실패로 세고 넘어가지 않는다 |
    | **검색어 문제** (그 주소 하나에만 해당) | `E0005`(검색어 미입력), `E0006`(주소를 상세히 입력 — 시도명만), `E0008`(두 글자 이상), `E0009`(문자와 숫자 같이 — 숫자만), `E0010`(검색어가 너무 김), `E0011`(너무 긴 숫자 포함), `E0012`(특수문자+숫자만), `E0013`(SQL 예약어·특수문자), `E0015`(검색 범위 초과) | 그 건을 **실패로 세고 "검색어 오류"로 분류**한 뒤 계속 진행한다. 재시도하지 않는다 |

  - 접근 문제로 멈출 때는 오류코드와 몇 번째 호출이었는지만 출력하고, **그때까지의 일치율은 계산·출력하지 않는다**(일부 결과를 보고 기준을 손대는 일을 막는다). 원인을 없앤 뒤 **같은 표본을 처음부터** 다시 잰다(멈춘 실행의 응답은 쓰지 않는다). 리포트에 멈춘 횟수와 오류코드를 적는다
- **실패 유형** (측정 전에 정함, 2026-10-13). 실패한 건은 위에서부터 처음 맞는 유형 하나로 분류한다

  | 유형 | 정의 |
  |---|---|
  | 검색어 오류 | 도로명주소 API가 "검색어 문제" 오류코드를 돌려줌 |
  | 통신 오류 | 3번 모두 통신 오류 |
  | 결과 없음 | 오류코드 `0`, 후보 0건 |
  | 여러 필지 건물 | 후보는 있으나 같은 PNU가 없고, 같은 검색어를 추가 항목(`addInfoYn=Y`)과 함께 다시 조회했을 때 어느 후보의 관련지번(`relJibun`)에 기록의 지번(법정동 이름·산 여부·본번·부번)이 있음 |
  | 지번 변경 (추정) | 위가 아니고, 후보 중 도로명주소(`roadAddrPart1`)가 검색어와 같은 것이 있음 — 같은 건물을 찾았으나 그 건물의 현재 지번·관련지번에 기록의 지번이 없다. 지번이 바뀌었는지 기록의 지번이 틀렸는지는 이 측정으로 가를 수 없다 |
  | 기타 | 나머지 (검색어와 같은 도로명주소의 후보가 없음 등) |

  - 다시 조회하는 것은 **분류에만** 쓴다. 일치 여부는 첫 조회(프록시와 같은 요청)의 후보 PNU로만 정하고, 관련지번에 있다고 일치로 바꾸지 않는다. 다시 조회도 1초에 1건·같은 중단 규칙을 따른다. 다시 조회가 통신 오류나 검색어 오류면 그 건은 "기타"로 둔다
- **나눠 보는 단위** (측정 전에 정함): 구는 기록의 `sigungu_code`, 개업연도는 `opened_on`의 해를 `1999년 이전 / 2000~2009 / 2010~2015 / 2016~2020 / 2021년 이후 / 개업일 없음`으로 묶는다. 나눈 값은 참고용이고 판정은 전체 값으로 한다
- **보고**: 판정은 점추정으로 한다. Wilson 95% 신뢰구간, 종단 값, 실패 유형별 건수를 함께 보고한다
- **판정**

  | 일치율 | 조치 |
  |---|---|
  | 95% 이상 | 통과 |
  | 90% 이상 95% 미만 | 실패 유형을 분류해 고친 뒤 다시 측정한다 (한 번만) |
  | 90% 미만 | Gate 1 보류 |

- **재측정**: 수정·재측정은 **한 번만** 한다. **새 seed(20261014)로 새 표본 2,000건**을 뽑는다 — 같은 표본으로 다시 재면 그 표본에 맞춘 수정이 점수를 부풀린다

  | 재측정 일치율 | 조치 |
  |---|---|
  | 95% 이상 | 통과 |
  | 90% 이상 95% 미만 | Gate 1은 진행하되 조건 두 가지: ① 주소 검색이 안 될 때 지도에서 직접 고르는 길이 있을 것(T-032) ② 방법론 페이지에 일치율을 공개할 것 |
  | 90% 미만 | Gate 1 보류 |

  - ①은 docs/40 §4.2 "지도에서 고르기"(T-032)다. ②는 조건이 걸리면 docs/40 §4.9에 항목을 먼저 넣는다 (AGENTS.md §1)

#### 최근 기록 층 확인율

- **측정**: 2016-01-01 이후 개업한 기록 중 층이 파싱된(층 파서가 층을 읽은 — docs/10 §3) 기록의 비율
- **분모에서 빼는 것**: 고정된 자리가 없는 업태(`no_fixed_place`, docs/10 §1.1) — 원래 층이 없는 것이 정상이다. 뺀 건수를 함께 적는다
- **보고**: 구별 값도 함께 보고한다. **판정은 서울 전체 값으로** 한다
- **판정**

  | 층 확인율 | 조치 |
  |---|---|
  | 70% 이상 | "층 이력" 표현 유지 |
  | 50% 이상 70% 미만 | 층 페이지에 층 확인 비율을 함께 표시한다 |
  | 50% 미만 | 화면의 기본 단위를 필지(건물)로 바꾸고 층은 보조 정보로 둔다 |

- 70% 미만이 나오면 조치에 맞춰 docs/40·docs/30을 먼저 고친다 (AGENTS.md §1)
