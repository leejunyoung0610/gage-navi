# 22. 폐업 지원 모듈 (`closure`)

> 폐업내비 설계 v0.2(2026-10)를 공통 규칙 엔진 위로 옮긴 것. 지역은 부산 → 서울로 변경(ADR-018).

## 1. 목표

- **사용자 질문**: "문 닫을 때 받을 수 있는 지원을 놓치지 않으려면 무엇을, 어떤 순서로, 언제까지 해야 하나?"
- **기본 목적**: `max_benefit`(예상 지원액 최대) + `certainty_first`(확실성 우선) 2안
- 폐업만 권하지 않는다: 경영개선 지원(계속 운영 선택지)을 결과에 항상 함께 보여준다

## 2. 대상 사업 (MVP)

| 구분 | 사업 | 비고 |
|---|---|---|
| 전국 | 희망리턴패키지 원스톱폐업지원: 점포철거비 / 사업정리컨설팅 / 법률자문 / 채무조정 | 공고 1건 → 사업 4개 (extraction_item 4개) |
| 전국 | 희망리턴패키지 전직장려수당, 재기사업화 | 폐업 후 단계 |
| 전국 | 희망리턴패키지 경영개선 지원 | 계속 운영 선택지 |
| 서울 | 서울시 폐업(사업정리) 지원사업 | 🔎 T-070 공고 확인. 철거비 등 소진공 사업과 충돌 조건 원문 확인 |
| 행정 | 통합 폐업 신고, 폐업 시 부가세 확정신고 | 법정 기한 레지스트리 + 공식 링크 |

**금액·조건 원칙**: 조사 과정에서 같은 철거비 지원이 출처마다 250만/300만/400만/600만 원으로 다르게 돌아다니는 것을 확인했다. 원문 확인 값만 쓴다.

## 3. 프로필 입력 (정책자금과 공통 필드 재사용 + 아래 추가)

| 질문 | 필드 | 입력 |
|---|---|---|
| 지금 상태는? | `business.status` | 운영 중 / 폐업 예정 / 폐업함 |
| 폐업 예정일 또는 폐업일 | `business.closure_planned_on` / `business.closed_on` | 날짜 |
| 점포 사용 형태 | `store.tenancy` | 유상 임차 / 무상 임차 / 자가 |
| 점포 면적 | `store.area` | 숫자 + 단위(㎡/평) + 기준(전용/계약/모름) |
| 철거 견적 공급가액 | `store.demolition_quote_supply_krw` | 금액(선택) |
| 임대차 만료일 | `store.lease_end_on` | 날짜(선택) |
| 철거 공사를 시작했나요? | `store.demolition_started` | 예/아니오 |
| 받은 적 있는 지원 | `history.received` | 희망리턴패키지 항목, 다른 기관 철거비 지원 |
| 고용보험 가입 | `owner.employment_insured` | 예/아니오/모름 |

## 4. 규칙 작성 시 주의 (검수 체크리스트)

- 철거비는 `benefit.amount.type = per_area` + `actual_cost = supply_value` (실비 정산) — 견적이 상한보다 낮으면 견적액
- 면적 기준(`area_basis`)·반올림(`rounding`)이 원문에 없으면 `unknown` (추측 금지)
- "중복 **신청** 불가"와 "중복 **수혜** 불가"를 구분해 `scope` 설정. 구분 불가 → `unknown`(엔진은 `apply`로 보수 처리, ADR-008)
- 배제 조건이 한쪽 공고에만 있어도 그대로 입력(엔진이 양방향 적용)
- "철거 전 신청" 같은 순서 조건은 `procedure`로 (`{"step": "apply", "before": "demolition_start"}`)
- "폐업 후 N개월 이내" → `elapsed_months_lte` + 사실 `business.closed_on`
- 무상 임차·자가는 철거비 대상이 아닌지 원문 확인 후 `store.tenancy` 조건으로

## 5. 타임라인 (closure 기본 노드)

```
apply(철거비 등 사전 신청) → [선정·진단] → demolition_start → demolition_done(세금계산서 수취)
→ evidence_submit → closure_report(폐업 신고) → vat_final_return → (폐업 후 사업 신청)
```
- `vat_final_return` 날짜 = 법정 기한 레지스트리 `vat_closure_final_return`: **폐업일이 속한 달의 다음 달 25일** (docs/03 R3). 예: 폐업일 2026-11-10 → 2026-12-25 (주말·공휴일 연장은 MVP에서 계산하지 않고 "기한이 휴일이면 다음 영업일" 문구만 표시)
- 경고:
  - `demolition_started_blocks`: 철거를 이미 시작했으면 사전 신청형 철거비는 불충족 + "철거 공사를 먼저 시작하면 지원받을 수 없어요"
  - `lease_end_conflict`: 선정형 사업이 계획에 있고 임대차 만료일까지 60일 미만이면 "선정 결과를 기다리다 원상복구 기한을 넘길 수 있어요"

## 6. 함정 체크리스트 (결과 화면 고정 섹션, 해당하는 것만 표시)

| 조건 | 문구 |
|---|---|
| 사전 신청형 사업이 후보 | "철거 공사 전에 먼저 신청해야 해요" |
| 폐업 신고 전 신청 조건 사업이 후보 | "폐업 신고 전에 신청해야 하는 지원이 있어요" |
| 생애 1회 사업 | "평생 한 번만 받을 수 있어요. 지금 받을지 확인하세요" |
| 부가세 확정신고 | "폐업일이 속한 달의 다음 달 25일까지 부가세 확정신고를 해야 해요" |
| benefit 충돌 쌍 | "둘 다 신청할 수 있지만 하나만 받을 수 있어요" |

## 7. 시나리오 테스트 (가상 규칙 픽스처, 고정 as_of)

| ID | 상황 | 기대 |
|---|---|---|
| C-S1 | 20평 vs 30평에서 서울/소진공 철거비 추천이 뒤집히도록 만든 가상 단가·상한 | 면적에 따라 선택 사업이 바뀜 |
| C-S2 | 철거 착수 = 예 | 사전 신청 철거비 NOT_MET + `demolition_started_blocks` |
| C-S3 | 과거 철거비 수혜 | 생애 1회 사업 NOT_MET |
| C-S4 | 매출 미입력 | 매출 조건 사업 UNKNOWN + `missing_facts` |
| C-S5 | 이미 폐업, 폐업 후 7개월, 규칙은 6개월 이내 | NOT_MET |
| C-S6 | 자격 충족 + 접수 마감 | 계획 제외, "다음 공고" |
| C-S7 | 충돌 scope apply vs benefit | apply: 하나만 / benefit: 둘 다 + `alternatives` |
| C-S8 | 견적 공급가액 < 면적 기준액 | 예상액 = 견적액 |
| C-S9 | 면적 기준 사용자 전용 vs 규칙 계약 | `area_basis_mismatch` 플래그 |
| C-S10 | 폐업일 2026-11-10 | `vat_final_return` = 2026-12-25 |
| C-S11 | 무상 임차 | 철거비 NOT_MET (가상 규칙의 tenancy 조건) |
| C-S12 | 임대차 만료 40일 전, 선정형 철거비 | `lease_end_conflict` |
